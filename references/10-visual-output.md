# 10｜视觉输出规则 V1.1

## 默认目的

视觉化是为了降低教师理解负担，不是为了让错误内容看起来更专业。

## 顺序

**先过科学准确 → 儿童发展 → 探究价值 → 再视觉化。**

## 默认视觉结构

优先使用柔和、低饱和、易扫读的区块：

### 【给老师看的】
科学解释、不确定性、变量、教师诊断。

### 【给儿童经历的】
儿童问题、可操作经验、可见证据、教师支架。

两类内容必须清楚分开。

## HTML

用户提出“图文并茂 / HTML / 科普卡 / 一眼看懂”时：
- 米白 / 浅色背景；
- 浅绿、浅蓝、浅黄等柔和色块；
- 一页一个重点；
- 不超过 4—6 个主区块；
- 允许 CSS 简图、箭头、对比框；
- 不依赖外部 JS / CSS；
- 适合投屏和手机；
- 重要的不确定性不能藏在脚注里。

## 禁止

- 把候选原因画成“确定原理”；
- 把教师诊断流程画成“儿童课程流程”；
- 为了漫画感把科学机制拟人化成错误解释；
- 用装饰替代证据；
- 编造测量数据。
