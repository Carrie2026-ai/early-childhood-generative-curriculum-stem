# 04｜幼儿工程设计规则 V1.1

## 核心区别

科学更多指向解释现象，工程更多指向解决真实需要。

当儿童已经拥有真实需要并在测试自己的方案时，**不要为了展示科学探究而把工程主线拆成低水平的科学验证。**

## 工程问题五要素

1. 真实需要：到底要解决什么？
2. 成功标准：怎样算能用 / 更好？
3. 限制条件：材料、时间、空间、安全、儿童能力。
4. 多个可能方案：不能只有教师预设唯一做法。
5. 测试与改进：方案必须经过使用 / 测试，根据证据调整。

## 推荐循环

**发现需要 → 想办法 → 表征 / 制作 → 测试 → 对照标准 → 解释哪里没达到 → 修改 → 再测试**

## 科学如何自然进入工程

教师先在后台理解相关科学机制。

只有当某个科学问题能帮助儿童：
- 解释为什么方案没达到标准；
- 比较不同方案；
- 决定下一次改什么；

才把它带到儿童层面。

**教师为了排查原因做的测试，不必全部交给儿童。**

## 数学如何自然进入

当儿童需要：
- 测长度；
- 数数量；
- 比多少；
- 记录时间；
- 比较前后结果；

数学成为让工程证据更清楚的工具。

## 失败规则

失败首先是数据，不是课程失败。

优先问：
- 哪个标准没达到？
- 儿童怎么解释？
- 新证据改变了什么？
- 下一步儿童最想改什么？
- 教师需要补懂哪些科学，而不是马上告诉儿童什么？

## 红线

- 不把手工自动认定为工程；
- 不把成人代做的复杂装置当儿童工程；
- 不把真实工程问题降成无关的常识验证；
- 不为了 S/T/E/M 齐全增加无关实验。
